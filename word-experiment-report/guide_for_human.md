# Word experiment report skill 使用指南

这个 skill 是一个可复用的报告工作目录。它不要求每次都使用当前项目里的 MySQL 文件；当前目录中的实验报告、实验指导书和往年报告只是示例资料。

## 一、创建新的报告项目

推荐先复制 `workspace-template/`，或者运行（没有实际模板时，可同时复制数模版式参考）：

```powershell
.\scripts\new_report_workspace.ps1 -ProjectRoot "D:\path\to\your-report" -CopyMathModelReference
```

新项目默认包含：

```text
your-report/
├─ input/                 # 本次作业说明、实验指南、题目和原始数据
├─ references/            # 可选模板、往年报告、格式参考
├─ code/                  # SQL、Python、脚本、备份和最终验证代码
├─ screenshots/           # 提问图、模型回答图、执行结果图、报错图
├─ working/               # 编辑中的 Word 和中间文件
├─ output/                # 最终 DOCX 和 PDF
└─ qa/                    # 渲染后的页面 PNG 和检查记录
```

## 二、用户需要放什么文件

### 1. 必须或通常需要放入 `input/`

- 本次课程或实验的指导书、任务书或评分要求。
- 题目清单、自然语言问题、数据字典或表结构说明。
- 如果没有正式指导书，至少放一份包含实验要求的文本或 PDF。

### 2. 可选地放入 `references/`

- **实际 Word 模板**：如果老师提供了模板，放入这里，优先级最高。模板可以是 `.docx`、`.docx` 或可读取的 Word 文件。
- **往年报告**：用于参考结构、图表密度和表达方式，不作为事实来源。
- **通用版式参考**：没有实际模板时，可以使用 `workspace-template/references/数学建模国赛标准论文Word模板.doc`，参考字体、字号、行距、缩进、对齐、页边距和页面平衡。
- 本次实验的指导书或往年报告只在它们确实适用于当前任务时复制；不要把上一个课程项目的专用资料当成通用要求。

### 3. 放入 `code/`

- 可直接运行的 SQL 或程序代码。
- 数据库创建、表结构、初始化数据、查询、验证、备份和恢复脚本。
- 如果代码在平台中运行，平台执行命令或导出的代码也应保存下来。
- 报告中展示的代码必须能在这里找到完整版本；报告里的长代码可以节选，但要注明完整文件名。

### 4. 放入 `screenshots/`

- 每个问题或子问题的题目/提示词图（如果任务要求保留）。
- 模型回答或代码生成图（如果使用大模型）。
- 数据库执行结果图。
- 报错图和修正后的成功结果图；报错有助于解释解决方案时不要删除。

## 三、模板选择规则

按下面顺序选择格式来源：

1. 用户或老师提供的本次实际 Word 模板。
2. 当前项目已有的、用户明确要求沿用的报告。
3. skill 自带的数学建模模板，仅作为字体、字号、行距、缩进、对齐、页边距和页面布局参考。
4. 没有任何参考文件时，使用清晰、稳定、适合打印的普通 Word 报告样式。

数模模板不能决定实验报告的章节内容，也不能覆盖指导书规定的问题、编号或提交要求。

## 四、写作和证据要求

每一问或每一个子问题，尽量按以下顺序写：

1. 问题/任务描述。
2. SQL 或程序代码。
3. 执行结果和回答。
4. 结果截图及图注。
5. 必要时补充报错原因、修正过程和最终判断。

如果一个问题包含 A、B、C 三次提示或三种方案，A、B、C 都应分别保留代码、回答和结果图，再写比较结论。顶层编号必须唯一；增加第二个线下实验时，应放在线下实验这一大节下面，不能重新生成一个重复的顶层“三”。

## 五、交付前检查

- 可编辑 DOCX 放在 `output/`。
- PDF 从最后一次通过渲染检查的 DOCX 导出并放在 `output/`。
- 完整代码、原始材料和截图仍保留在项目目录中。
- 使用文档 skill 的 `render_docx.py` 渲染 DOCX，并逐页检查标题编号、中文字体、代码换行、截图清晰度、图注、表格、页码和空白页。
- 只有最后检查通过的 DOCX 和 PDF 才作为最终交付文件。
